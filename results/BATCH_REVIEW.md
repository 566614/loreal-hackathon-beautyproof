# BeautyProof 批量审核队列（batch_review）

> 给评审 / 老板看的功能说明

## 一、解决什么痛点

品牌方一天要过**成百上千张**素材（达人图、电商图、社媒图），单张鉴定工具 `tools/pipeline.py`
一次只能看一张、还要人守在旁边一张张拖——这在大规模审核场景下不现实。

批量审核队列把「整个目录一键过」变成现实：

- 一次性把目录下所有 `png/jpg/jpeg/webp` 跑完鉴定流水线；
- 把每张图的**风险结论 + 关键证据**汇总成一张清单；
- 再生成一份**按风险排序的静态看板**，双击就能看、能直接转发给非技术同事复核。

## 二、怎么用（一条命令）

```bash
# 默认 --fast：跳过最慢的 AIGC/OCR 提速，TruFor 篡改检测仍跑（推荐）
python tools/batch_review.py <图片目录>

# 跑完整套（含 AIGC + OCR，信息最全但最慢）
python tools/batch_review.py <图片目录> --full

# 自定义输出目录（默认 outputs/batch/<run_id>/）
python tools/batch_review.py <图片目录> --out <输出目录>
```

- 环境必须用项目隔离 venv 的 Python（系统 Python 缺包）：
  `C:/Users/Lenovo/.workbuddy/binaries/python/envs/default/Scripts/python.exe`
- `<图片目录>` 只取**一层**内的图片（不递归子目录），避免误吞无关文件。
- 每张图的处理互相隔离：**某张图报错不会中断整个队列**，会被记进 `failed` 列表，最后照常出报告。

## 三、输出什么

所有产物落在 `outputs/batch/<run_id>/`（`<run_id>` 是运行时间戳，便于多次运行归档对照）：

| 文件 | 给谁看 | 内容 |
|------|--------|------|
| `summary.json` | 程序 / 下游 | 每条 `{stem, risk_level, risk_zh, trufor_score, ratio, position, aigc_prob, needs_review, ...}`，中文 `ensure_ascii=False` 原样保存 |
| `summary.csv`  | 非技术同事 | 用 **utf-8-sig** 编码，Excel 双击直接打开、中文不乱码 |
| `index.html`   | 所有人 | 静态看板，按风险排序（高风险最上），每图含缩略图 + 证据要点 + 定位图链接，纯静态双击可看 |
| `loc/`         | （html 用） | 拷贝进来的 TruFor 定位图（热力图/叠加图），让 html 自包含、不依赖原图路径 |

看板排序规则：先按风险档（高→可疑→可信→无法判定），同档内按 TruFor 篡改分从高到低。
`needs_review = 高风险 或 可疑`，即「建议人工复核」的两档合计。

## 四、与单图鉴定的关系

- 批量队列**完全复用**单图流水线 `tools/pipeline.py` 的 `analyze()`，鉴定口径、规则引擎、
  证据格式与单图报告 **100% 一致**，不会出现「批量松、单图严」的双标。
- 单图鉴定适合「拿一张可疑图出正式报告（含 PDF）」；批量队列适合「先大面过一遍、把要复核的挑出来」。
  工作流建议：**批量过筛 → 高风险/可疑的图再用单图鉴定出详细 PDF 报告**。

## 五、速度设计（为什么快）

TruFor 是真正的「篡改检测」深度学习模型（CVPR 2023），也是本工具的核心信号，但加载几百 MB 模型很慢。
本工具的关键优化：**对整个目录先做一次 TruFor 批量推理，模型只加载一次**（远快于逐张加载）。
`--fast` 在此基础上再跳过最慢的 AIGC 与 OCR，进一步提速——但**篡改检测不打折**。

> ⚠️ 注意：TruFor 有结果缓存（key = 图片绝对路径），同一张图第二次跑直接命中缓存、不重算模型。
> 所以「同一批图重复跑」会很快。

## 六、已知边界（务必如实告知品牌方 / 法务）

1. **`--fast` 跳过 AIGC / OCR**：这两项是「锦上添花」信号。AIGC 检测在本批素材上实测
   **零区分度**（真实图 0.9571 vs 篡改图 0.9621），本就不参与自动定级，仅作参考；
   OCR 是文案比对。若需要这两项，请改用 `--full`。
2. **AI 整图生成 ≠ 直接判定**：TruFor 擅长查「局部被人动过手脚」，**查不出「整张完全由 AI 生成的图」**
   （官方模型本身的能力边界）。目前对「整图 AI 生成」只能靠 TruFor 高分**间接**标记为可疑/高风险，
   而非直接给出「AI 生成」结论。这一点在单图报告和规则引擎里都有明确声明。
3. **`needs_review` 是建议，不是判决**：所有结论来自算法比对，不是法律意义上的鉴定意见。
   分数高不代表一定有罪（压缩、滤镜也会留痕），分数低也不代表绝对干净。
4. **一层目录**：只扫目录直接子文件的图片，不会递归进子目录；需要递归请先把图片归并到一个文件夹。
