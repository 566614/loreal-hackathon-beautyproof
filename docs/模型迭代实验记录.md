## 轮次 3 —— 阈值扫描（变量 = 阈值；模型权重 / 数据 / 预处理 / 融合全部不动）

| 字段 | 值 |
|---|---|
| 模型版本 | `beautyproof_aigen_v4`（**权重未动**） |
| 数据版本 | `results/closedloop_eval.json`（`generated_at 2026-09-28T20:29:50`）里的两个冻结集 |
| 阈值 | 扫描 0→1 共 **101 档**；当前生产 0.9 |
| 运行命令 | `python tools/threshold_sweep.py` |
| 混淆矩阵 | 基线（t=0.9）：TP=8、FN=4、FP=1、TN=9 |
| 误报/漏报 | **无任何阈值能提升召回**（`better_recall_points` 为空）；t∈[0.98, 0.99] 可在不损召回的前提下把高风险误报 0.1→0，但区间宽仅 **0.01** |
| 耗时 | < 1 s（纯统计，不跑模型） |
| 判定 | `FOUND_BUT_FRAGILE` → **不改生产阈值**，仅记录边界 |

**关键发现（这一条解释了 v6 为什么失败）：**
真实图最高分 **0.9792**，被判出的 AI 图最低分 **0.9994**——判别面是**饱和**的，
阈值这个变量根本没有可调节余量。所以跨生成器召回不是「阈值没调好」，
而是模型判别面本身没拉开；靠调阈值救不回来。

**为什么不采纳 0.98：** 那个零误报区间是靠「恰好卡掉那一张 0.9792 的误报样本」得到的，
属于对单样本的贴合（过拟合）；且抬高阈值会压缩未见生成器的判出空间
（新生成器的分数可能落在 0.9x），反而伤害我们本就最弱的召回。按 reviewer
「不显著改善就不替换」的口径，记录但不采纳。
