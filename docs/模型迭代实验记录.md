## 轮次 3 —— 阈值扫描（变量 = 阈值；模型权重 / 数据 / 预处理 / 融合全部不动）

| 字段 | 值 |
|---|---|
| 模型版本 | `beautyproof_aigen_v4`（**权重未动**） |
| 数据版本 | `results/closedloop_eval.json`（`generated_at 2026-09-28T20:29:50`）里的两个冻结集 |
| 阈值 | 扫描 0→1 共 **101 档**；当前生产 0.9 |
| 运行命令 | `python tools/threshold_sweep.py` |
| 混淆矩阵 | 基线（t=0.9）：TP=8、FN=4、FP=1、TN=9 |
| 误报/漏报 | **无任何阈值能提升召回**（`better_recall_points` 为空）；t∈[0.98, 0.99] 可在不损召回的前提下把高风险误报 0.1→0，但区间宽仅 **0.01** |
| 耗时 | < 1 s（纯统计，不跑模型） |
| 判定 | `FOUND_BUT_FRAGILE` → **不改生产阈值**，仅记录边界 |

**关键发现（这一条解释了 v6 为什么失败）：**
真实图最高分 **0.9792**，被判出的 AI 图最低分 **0.9994**——判别面是**饱和**的，
阈值这个变量根本没有可调节余量。所以跨生成器召回不是「阈值没调好」，
而是模型判别面本身没拉开；靠调阈值救不回来。

**为什么不采纳 0.98：** 那个零误报区间是靠「恰好卡掉那一张 0.9792 的误报样本」得到的，
属于对单样本的贴合（过拟合）；且抬高阈值会压缩未见生成器的判出空间
（新生成器的分数可能落在 0.9x），反而伤害我们本就最弱的召回。按 reviewer
「不显著改善就不替换」的口径，记录但不采纳。

**关键发现（三轮样本实验的共同规律）：**
「压精致滤镜自拍误报」与「跨生成器召回」是**跷跷板**——v5 加真人标注真实图、
v6 加 Flux、v7 加滤镜自拍，三次都是真实类一改善、跨生成器召回就掉。
百余张量级的训练集里，两个方向在特征空间挤同一段判别面；这不是「再多来几张」
能解决的，需要成量级的两类难例（各 10–30 张只是起步）加置信度校准/弃权带才可能同时改善。

## 轮次 5 —— 决策政策：AIGC 灰带（变量 = 阈值解释方式，**模型零改动**）

> 动机：v5/v6/v7 三轮证明「压真实滤镜自拍误报 ↔ 跨生成器召回」是跷跷板，靠改模型走不通。
> 但冻结集分数暴露了一个此前没利用的**结构**：真实图误报全部落在 0.9154~0.9842，
> 而被捕获的 AI 图**全部 ≥ 0.9959**（漏掉的 AI 图则是 0.0，整段出界）。两段之间有一条干净缝。

| 字段 | 值 |
|---|---|
| 模型版本 | `beautyproof_aigen_v4`（**零重训、零改动**） |
| 变量 | rule_engine 对 AIGC 分数的解释方式：`≥0.9 → high_risk` 改为 `≥0.99 → high_risk；[0.9, 0.99) → suspicious（人工复核，不自动下架）` |
| 阈值 | `aigc_hard_high 0.99`（新增）/ `aigc_high_risk 0.9`（语义变为灰带下限）/ `aigc_abstain 0.2`；`aigc_suspicious 0.8` 档位取消 |
| 运行命令 | `python tools/eval_abstain_band.py`（基于 `results/v7_eval.json` 中 v4 冻结集真实分数模拟新旧政策） |
| 结果（`results/abstain_band_eval.json`） | 真实图自动下架级误伤 **3 → 0**（0.9154 / 0.9792 / 0.9842 全部降级为人工复核）；AI 图捕获 **27 → 27（零丢失）**；漏检 AI 图（0.0 出界段）不受影响 |
| 判定 | 三项检查全 PASS → **ADOPT_BAND，已进入生产规则引擎** |

**为什么这不是又一次「调阈值」：** 阈值扫描（轮次 3）卡的是「真实误报最大 0.9842」那一个样本，
窄区间 0.01、对单样本贴合；灰带利用的是**两段分数分布之间的整条缝**（0.9842 与 0.9959 之间），
且方向是「把模糊的降级为人工复核」而不是「把临界的抬进自动下架」——前者对未知分布安全
（最坏情况只是多一条人工复核），后者对未见生成器脆弱。灰带同时兑现赛题要求的
「风险预警与处理建议」：灰带样本不自动下架、直接进人工复核队列，处置更合理。

**边界（诚实声明）：** 灰带边界 0.99 是在当前冻结集分布上标定的；若未来某类真实图分数
越过 0.99，仍会被自动下架级误伤——所以 held-out 误报监测必须常态化，灰带边界随数据更新。
