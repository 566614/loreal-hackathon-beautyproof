## 四、关键代码修改实现（真实落盘代码，非设想）

### S1 · 视频接入：`tools/pipeline.py`

```python
VIDEO_EXTS = {".mp4", ".mov", ".avi", ".webm", ".mkv"}

def is_video_input(p):
    """这个输入是不是视频：扩展名命中即可；传目录时，目录里含视频也算。

    为什么要认目录：赛题素材包常是「一个文件夹里一堆 mp4」，让评委挨个敲路径不现实。
    目录里既有图又有视频时，视频归视频、图归图（见 expand_video_inputs）。
    """
    p = Path(p)
    if p.is_dir():
        try:
            return any(f.is_file() and f.suffix.lower() in VIDEO_EXTS
                       for f in sorted(p.iterdir()))
        except Exception:  # 目录不可读就当它不是视频目录，走原逻辑报错
            return False
    return p.suffix.lower() in VIDEO_EXTS
```

- 配套 `expand_video_inputs()` / `run_video_input()`，在 `main()` 里把视频扩展名转调 `run_video`，并透传 `--fast / --json-only / --llm / --roundtable / --max-frames / --fps-sample`。
- **红线守住**：`analyze()` 与图像主路径一行未动；已验证 `python tools/pipeline.py data/clean/clean_01.png --fast --json-only` 行为与改动前一致。
- 视频产物沿用统一证据格式（`source_asset_id` / `frames[]` / `risk_level` / `reasons` / `cannot_prove`），报告里明写局限：本次只分析 6/4958 帧（覆盖率 0.12%），不证明未抽到的帧干净。

### S2-2 · 决策链路导出：`tools/pipeline.py`

```python
def _contributing_tools(reasons):
    """从规则引擎 reasons 反查「哪些工具的证据直接推动了最终档位」

    只把"抬高了档位"的工具算进来：带工具前缀、且不是上述负面/弃权措辞的理由。
    例如 aigc 给出 0.0（<0.2，看起来像真实图）虽出现在 reasons 里，但它是**否定信号**，
    不应被记成"推动 high_risk 的元凶"——真正推动的是 TruFor。
    """
    contrib = set()
    for r in (reasons or []):
        if any(m in r for m in _NEGATIVE_MARKERS):
            continue
        for hint, tool in _REASON_TOOL_HINTS:
            if hint in r:
                contrib.add(tool)
                break
    return contrib
```

`build_decision_trace(stem, image_name, risk_level, reasons, evidence)` 在 `analyze()` 成功时写出 `outputs/decision_trace_<图名>.json`：`trace[]` 每项含 `tool / observed / evidence_ref(→outputs/<tool>_<stem>.json) / contributed_to_risk_level`，外加 `risk_level / reasons / action_playbook`。

实跑验证：全量模式 `tampered_01_copy_move` → `high_risk`，trace 中**仅 trufor 标记 contributed=True**，aigc（0.0）被正确排除。
