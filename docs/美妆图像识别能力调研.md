# 美妆图像识别能力调研报告

> 调研对象：妆容识别 / 品类识别 / 肤色识别 / 虚拟试妆
> 调研日期：2026-09-26
> 用途：评估是否可复用现成能力，或需自建数据与模型

---

## 0. 阅读须知：本报告的可信度分级

你要求"区分已证实信息与推测、不确定部分标注待核实"。本报告全文使用以下三个标记：

| 标记 | 含义 | 你能怎么用 |
|---|---|---|
| ✅ **已证实** | 有官方论文 / 官方站点 / 官方定价页可核查，附来源链接 | 可直接写进方案、对外承诺 |
| ⚠️ **推测** | 基于行业公开信息的合理推断，无一手来源 | 只能做内部假设，需验证后再对外 |
| ❓ **待核实** | 关键但拿不到/没拿到一手证据，或数字存疑 | 必须先补证据再决策 |

**一个必须先说清楚的口径问题**：你问的"该识别模型"，在外界其实对应**三类完全不同的对象**，它们的数据规模差 2~3 个数量级，不能混为一谈：

1. **学术公开模型**（BeautyGAN / PSGAN / 肤色分类 baseline）——训练数据**公开可查**，规模在**数千张**量级；
2. **欧莱雅体系内能力**（ModiFace / Beauty Genius / SkinConsultAI）——训练数据**全部内部、不可核实**；
3. **通用视觉多模态大模型零样本路线**（CLIP / GPT-4V / Qwen-VL 等）——**不需要你的训练数据**，但精度与稳定性是另一种风险。

# 一、训练数据规模与来源

## 1.1 结论速览（先看这张表）

| 能力 | 公开可查的标注数据量级 | 最好的公开数据集 | 是否够用 |
|---|---|---|---|
| **妆容识别**（有妆/无妆） | **10³ ~ 10⁴ 张**（数千张） | MT dataset（BeautyGAN）3,834 张 | ❌ 做 Demo 够，做产品不够 |
| **妆容迁移/虚拟试妆** | 同上 | MT + Makeup-Wild | ❌ 同上 |
| **肤色识别** | **1.6×10⁴ 张**（但属医学域） | Fitzpatrick17k 16,577 张 | ⚠️ 域不匹配，见 1.4 |
| **品类识别**（口红/粉底/眼影…） | **基本为 0** | 无权威公开集 | ❌ **这是最大缺口** |
| **通用人脸属性** | 2×10⁵ 张 | CelebA 202,599 张 | ⚠️ 只有属性，无品类/肤色 FST |

一句话：**"妆容识别"有数据但是玩具级；"肤色识别"有数据但是医院里的图；"品类识别"没有公开数据。**

## 1.2 公开数据集明细（✅ 可核查）

### （1）MT dataset（BeautyGAN 数据集）——妆容识别的事实标准基线

| 项 | 内容 |
|---|---|
| **规模** | **3,834 张**女性面部图像（1,115 张素颜 + 2,719 张带妆） |
| **分辨率** | 256×256（部分资料记为 361×361，❓**建议以官方发布包为准**） |
| **标注方式** | 68 个人脸关键点（人工/自动关键点检测器）+「有妆/无妆」二分类标签 |
| **采集方式** | 网络爬取 + 人工筛选清洗 |
| **来源** | 中山大学 HCP 实验室，BeautyGAN 论文（ACM MM 2018）配套发布 |
| **可查性** | ✅ 论文与项目页公开 |

**已知偏差（必须知道，否则会踩坑）**：
- 浓妆样本远多于淡妆 → 模型对淡妆识别能力天然偏弱；
- **没有腮红标签**；
- **性别单一（仅女性）** → 男性妆容/跨性别场景直接失效。

### （2）Makeup-Wild（PSGAN 数据集）

| 项 | 内容 |
|---|---|
| **规模** | 约 **772 张**（403 张带妆 + 369 张素颜），❓ 具体数以论文/项目页为准 |
| **特点** | 相比 MT 更"野生"——姿态与表情变化更大 |
| **来源** | PSGAN 论文（CVPR 2020）配套 |
| **可查性** | ✅ 论文公开 |

⚠️ **重要提醒**：MT 与 Makeup-Wild 都是**妆容迁移（makeup transfer）**任务的数据集，标签只有"有妆/无妆"这一层。**它们不是"妆容识别"数据集，更没有品类标签和肤色标签。**很多文章把它们当"美妆识别数据集"引用，是误用。

### （3）Fitzpatrick17k —— 肤色标注最权威的公开集

| 项 | 内容 |
|---|---|
| **规模** | **16,577 张**临床皮肤科图像，覆盖 **114 种**皮肤病症 |
| **标注方式** | Fitzpatrick 肤色分型 **FST I–VI 六类**；由 **2–5 名非专家标注者**标注，通过 dynamic consensus 汇总；另有 **312 张**由皮肤科医生标注的金标准子集 |
| **来源构成** | DermaAmin 12,672 张 + Atlas Dermatologico 3,905 张 |
| **出处** | Groh et al., **CVPR 2021**；代码/元数据见 `github.com/mattgroh/fitzpatrick17k` |
| **可查性** | ✅ 论文 + GitHub 公开 |

**分布偏斜（这是它最大的问题）**：
- 浅肤色（FST I–II）约 **47%**
- 中间肤色（FST III–IV）约 **37%**
- 深肤色（FST V–VI）约 **13%**
- 其余少量未标注/存疑

**已知缺陷**：社区已报告存在**重复图像**与**标签错误**。用它训练前必须自行清洗。

⚠️ **域不匹配警告**：Fitzpatrick17k 全部是**皮肤病临床照片**（病灶特写、无妆、光照受控、多为躯干/四肢）。美妆场景是**带妆、有美颜/滤镜、光照随意、以面部为主**的照片。**直接拿它训"美妆图肤色识别"会严重漂移**——这和我们在 BeautyProof 上踩过的坑是同一类（见第三部分 3.4）。

### （4）通用人脸属性集（可作为预训练/辅助，但不是答案）

| 数据集 | 规模 | 有什么 | 没有什么 |
|---|---|---|---|
| **CelebA** | 202,599 张 / 10,177 个身份 | 40 个二值属性（含 Heavy_Makeup 等）、5 个关键点 | ❌ 无品类标签、❌ 无 FST 肤色标签 |
| **UTKFace** | 约 2 万+ 张 | 年龄 / 性别 / 种族 | ❌ 种族是粗粒度 5 类（White/Black/Asian/Indian/Others），**不是 FST 六级**；且该标签体系本身存在伦理争议 |

⚠️ 这两个数字为**广泛引用值**，建议以官方页面复核后再写进正式材料。

### （5）肤色量表：还有一个更适合的选项

- **Monk Skin Tone (MST) Scale**：Google 于 2022 年发布的 **10 级**肤色量表，相比 6 级的 Fitzpatrick，在深肤色区间划分更细、分布更均衡，且明确为"产品/技术包容性"场景设计。
- ✅ 已证实其存在与设计初衷；❓ 配套的公开标注图像集规模**待核实**（MST 更多是"量表 + 标注规范"，不是现成图片集）。

**选型建议**：如果你要做肤色识别，**优先采用 MST 十级作为标签体系、自建标注**，而不是硬套 Fitzpatrick17k。

## 1.3 欧莱雅 / ModiFace 体系内数据（❓ 无法核实）

这一节必须说实话：**拿不到。**

| 对象 | 公开表述 | 我们的判断 |
|---|---|---|
| **ModiFace** 训练数据规模 | **未公开** | ❓ 无法核实。可确认的是：欧莱雅 2018 年收购 ModiFace（金额约 1.4 亿美元量级，⚠️ 第三方报道，**待核实**），此后其数据与技术并入欧莱雅体系，不再对外披露 |
| **Beauty Genius** | 官方称基于**欧莱雅 116 年（或 100+ 年）护肤研究数据**构建"美妆知识图谱"，结合计算机视觉实时分析用户皮肤 | ✅ 该表述来自欧莱雅首席数字与营销官 Asmita Dubey 在 VivaTech 2026 的公开采访；⚠️ 注意她**明确否认它是 LLM**："It's not a large language model"——它是**知识图谱 + CV**，不是大模型 |
| **欧莱雅皮肤/头发数据总量** | 欧莱雅南亚太中东非总裁 Vismay Sharma 称公司"收集了超过 11 million gigabytes（1,100 万 GB）的头发和皮肤数据" | ⚠️ 此为**公开采访表述，量级存疑**（1,100 万 GB = 11 PB，作为单一消费品公司的皮肤/头发数据，数字异常大，可能为口径或引述误差）。**❓ 强烈建议标注为待核实，不要直接引用** |
| **SkinConsultAI** | 测肤老化、给护肤方案 | ✅ 存在；❓ 训练数据规模未公开 |
| **CreAItech** | 内部生成式 AI 内容实验室，整合 Google Imagen 3 / Veo、Adobe Firefly 等模型，月产能达 **5 万张图 + 500 条视频** | ✅ 已证实（36氪报道 + 欧莱雅官方场合引用）；⚠️ 这是**内容生产**能力，**不是识别能力**，也**不对外** |

**结论**：欧莱雅体系内的训练数据**没有一项是公开可查的**。你无法核实其规模、标注方式、人群分布。任何声称"欧莱雅用了 X 万张美妆图训练"的说法，在拿到官方数据披露前都应视为**不可信**。

## 1.4 品类与人群分布（关键缺口）

### 品类分布
- ❓ **没有任何公开的权威"美妆品类识别"数据集**（口红 / 粉底液 / 眼影盘 / 睫毛膏 / 遮瑕……）。
- ⚠️ **推测原因**：品类识别对欧莱雅是**核心商业资产**（直接关联商品推荐与转化），没有任何动机公开；而学术界缺乏标注预算与商品 SKU 数据源。
- **后果**：品类识别**必须自建数据**。这是本调研最硬的一个结论。

### 人群分布（公开数据的偏斜，全部 ✅ 可核查）

| 维度 | 公开数据的实际情况 |
|---|---|
| **肤色** | Fitzpatrick17k 深肤色仅约 13%，浅肤色约 47% → **显著偏斜**；MST 十级量表可缓解但需自建标注 |
| **性别** | MT / Makeup-Wild **仅女性**；CelebA 男女均有但属性标注不均衡 |
| **年龄** | 公开美妆数据以青中年为主，**中老年严重不足** |
| **地区/族裔** | 公开美妆数据以东亚/欧美面孔为主；临床数据（Fitzpatrick17k）以欧美皮肤病患者为主 → **中国人群代表性不足** |

⚠️ **这直接构成一个合规风险**：如果你的产品要做肤色/人群相关判断，而训练数据深肤色只占 13%，那么对深肤色用户的准确率会明显更低——这在欧美市场是会被监管和舆论直接质疑的。

# 三、信息缺失与替代选型建议

## 3.1 为什么确切数字拿不到（缺失原因）

| 缺失项 | 根本原因 |
|---|---|
| ModiFace / Beauty Genius 训练数据量 | 商业机密。欧莱雅的核心壁垒就是"百年研发数据 + 消费者诊断数据"，公开等于自毁护城河 |
| 美妆品类标注数据集 | 品类标签直接绑定 SKU 与推荐转化，是电商核心资产；学术界既无 SKU 源也无标注预算 |
| 中国人群美妆标注数据 | 采集涉及**人脸生物信息**，受《个人信息保护法》约束，合规成本极高，研究者不敢公开 |
| 通用人脸数据集的深肤色样本 | 网络爬取天然偏向高曝光人群，深肤色/中老年/非城市样本系统性不足 |

⚠️ **推测**：即使欧莱雅内部真的公开了数字，大概率也只会给"百年研究数据""千万级消费者诊断"这种**不可验证的营销口径**，而非可审计的训练集统计。**不要期待拿到精确数字。**

## 3.2 替代方案 A：自建数据集（推荐作为主力路线）

### 采集思路
1. **品类识别**：以**电商商品详情页主图 + 详情图**为主要来源（品类标签天然存在——商品标题/类目就是标签）。这是唯一低成本拿到品类标注的路径。
2. **妆容识别**：小红书 / 美妆社区公开帖文（注意：仅限**公开可爬、允许二次使用**的内容，且**不得采集人脸用于生物识别**）。
3. **肤色识别**：自有志愿采集（明确授权），或国际合作公开集补齐深肤色。

### 标注体系建议
- **肤色**：采用 **Monk Skin Tone 10 级**（不要 Fitzpatrick 6 级，后者深肤色分辨力不足）。
- **妆容**：分层标注（素颜 / 淡妆 / 浓妆）+ 部位标签（唇 / 眼 / 底妆 / 腮红 / 修容），不要只做二分类。
- **品类**：按 SKU 类目树标注，粒度定到"口红 / 粉底液 / 眼影盘"这一层即可，不要一步到位做单品识别。

### 标注方式与成本
- 单人标注 + **双人交叉复核 + 第三人仲裁**，标注者间一致性（Cohen's kappa）低于 0.6 的标签类别直接废弃重标。
- ⚠️ 参考 Fitzpatrick17k 的做法：它用 2–5 名**非专家**标注者 + dynamic consensus，并用 **312 张专家金标准**校准——这套流程你可以直接照搬，成本可控。

### 规模建议（⚠️ 推测，需按你的任务复杂度调）
| 任务 | 建议起始规模 | 理由 |
|---|---|---|
| 二分类（有妆/无妆） | 每类 1,000+ 张 | 简单任务，千级可见效 |
| 品类识别（10~20 类） | 每类 300~500 张 | 类间差异大，需覆盖包装/质地/上脸三种形态 |
| 肤色 10 级 | 每级 200~300 张 | **深肤色段必须单独补足**，不能靠自然分布 |

## 3.3 替代方案 B：通用视觉多模态大模型做零样本/少样本

**结论：可以做"冷启动验证"，不能做"最终交付"。**

### 适用性（✅ 有文献支撑）
- 零样本分类可在**没有训练数据**的情况下先跑通流程、验证需求是否成立，**成本几乎为零**（几十条 prompt 的时间）。
- **上下文学习（ICL，即少样本示例）能显著提升专用域表现**：CVPR 2025 的研究（Zhang et al., 评估 14 个 MLLM × 20 个数据集）指出，ICL 可显著改善 MLLM 在域外场景的泛化。
- **校准成本极低**：VLM 本身**不是天然校准好的**，但 temperature scaling 能稳定改善，**少于 100 个样本**即可完成校准，且对标签集/层级变化鲁棒。

### 局限性（❗这些是硬伤，必须写进方案）
1. **域专用任务上会大幅退化。** 上述 CVPR 2025 研究的核心发现：MLLM 在**医学、分子等专用域**图像上性能显著下降，主因是 **mapping deficiency**（领域视觉特征 → 语义标签的映射缺失），而非"看不清"或"不懂术语"。
2. **域漂移下零样本可能接近瞎猜。** Zhou et al.（arXiv 2405.12217）发现，在分布漂移场景中，预训练视觉编码器的零样本能力"**勉强优于随机猜测**"，且基于相似度检索的少样本示例选择会因此失效。
3. **少样本示例的选择极其敏感。** 同一篇 CVPR 2025 论文指出 ICL 对**域漂移、标签漂移、伪相关**都脆弱——示例选错，结果可能比零样本还差。
4. **输出不稳定、不可解释、难审计。** 你无法向评委/客户证明"为什么判成这一类"。
5. **成本与依赖。** 每次推理都要调用云端大模型；若你的场景要求离线或低延迟，直接出局。

### 一句话建议
> **用大模型零样本做"需求验证 + 打伪标签"，用打出来的标签训练小模型做"最终交付"。**
> 这条路我们在 BeautyProof 上已经跑通了一次（先用通用开源模型验证不可用，再本域微调小模型落地）。

## 3.4 来自本项目的实测教训（一手数据，强烈建议纳入你的评估）

⚠️ 这一段不是文献，是**我们自己在 BeautyProof 上跑出来的数字**，但它揭示的规律和上面所有文献完全一致，而且更贴你的场景：

| 指标 | 数值 | 说明 |
|---|---|---|
| 受控评测集准确率 | **100%**（35 张，含 7 张留出） | 看起来完美 |
| **真实小红书美妆图准确率** | **仅 34%**（56 张中 **66% 被误判为 AI 生成**） | **真实世界表现崩塌** |
| 根因 | 训练集只有"即梦 AI 图 vs 10 张原始手机照"，模型把"**滤镜+磨皮的美妆照**"也学成了 AI | **典型的域漂移** |
| 修复后（v2） | 真实误报 **66.2% → 1.4%**；未参与训练的验证集 **61.1% → 5.6%**；AI 召回保持 **100%** | 靠扩充真实类样本 + 针对性增强 |
| 仍未解决 | **跨生成器未验证**（AI 训练样本全部来自单一生成器"即梦"） | — |

**给你的三条铁律（可直接抄进你的评估标准）**：
1. **绝不在训练见过的图上评准确率**——会虚高到 100%，自欺欺人。
2. **对外汇报必须给"真实世界集"的数字**，不能给受控集的数字。
3. **先假设你的模型会在真实场景崩，再去证明它没崩**；而不是先假设它能用。

对照到本调研：**Fitzpatrick17k 训美妆肤色识别、MT 训真实场景妆容识别，都会复现上面这个 66% 误报的剧本。**

| 你的目标 | 推荐路线 | 理由 |
|---|---|---|
