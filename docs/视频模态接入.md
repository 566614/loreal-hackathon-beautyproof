# 视频模态接入（BeautyProof）

> 把视频接进 BeautyProof 现有的「图片取证流水线」：抽帧 → 逐帧跑 8 工具图像取证 → 聚合视频级判定。
> 配套评分目标：兑现赛题 `#多模态` 标签，对照评分方案的「完成度·需求匹配」与「技术难度·多模态」，**预期 +1~2 分**。

---

## 一、做了什么（不破坏现有图像流）

- 新增两个**独立模块**，没有改动 `pipeline.py` 里任何既有逻辑，也没有动 `analyze()`：
  - `tools/video_tool.py`：核心能力（抽帧 + 逐帧分析 + 聚合 + CLI）。
  - `tools/run_video.py`：连接器，把视频结果接到现有「证据 / 报告格式」，并产出视频级 Markdown 报告。
- 检测逻辑**完全复用**现有图像流水线（指纹 / C2PA / ELA / OCR / AIGC / TruFor / 文案 / 图文交叉），不重写任何一条检测。
- 每一帧的证据继续写进 `outputs/<tool>_<帧名>.json`，沿用统一格式
  `{tool, source_asset_id, observed, cannot_prove, evidence[]}`，
  其中 `source_asset_id` 就是这一帧的文件名 —— **帧天然复用了统一证据格式**，可单独追溯。

> 之所以不新增 `pipeline.analyze_video`，是因为 `video_tool` 直接 `import pipeline` 并逐帧调用 `pipeline.analyze()` 即可，零侵入、零风险。

## 二、怎么对 11 个 mp4 运行

**前置**：opencv 已装在项目 venv（`cv2 5.x`）。若未装，用 venv 自带 pip 安装（绝不用系统 pip）：
```bash
C:/Users/Lenovo/.workbuddy/binaries/python/envs/default/Scripts/pip.exe install opencv-python-headless
```
运行统一用项目 venv 的 python：
```bash
PY="C:/Users/Lenovo/.workbuddy/binaries/python/envs/default/Scripts/python.exe"

# 方式 A：video_tool 直接出 JSON（命令行）
$PY tools/video_tool.py --input data/xxx.mp4 --out outputs/analysis_video_xxx.json

# 方式 B：run_video 出 JSON + Markdown 报告（推荐，给评委/人工看）
$PY tools/run_video.py --input data/xxx.mp4

# 批量跑 11 个（示例，bash）
for f in data/*.mp4; do
  $PY tools/run_video.py --input "$f" --fast   # 先 fast 批量预览
done
# 对 flagged 的视频再用 full 模式复核（含 AIGC / TruFor 深度学习模型）
$PY tools/run_video.py --input data/可疑.mp4    # 不带 --fast 即 full
```

**常用参数**（两个脚本通用）：
| 参数 | 含义 | 默认 |
|---|---|---|
| `--input` | 输入视频（必填） | — |
| `--fast` | 跳过 aigc / trufor 深度学习模型，秒级出结果（仅预览） | 关 |
| `--max-frames` | 最多抽多少帧（控成本） | 30 |
| `--fps-sample` | 抽帧采样率，每秒抽几帧 | 1.0 |
| `--out` | 结果 JSON 输出路径（仅 video_tool） | `outputs/analysis_video_<名>.json` |

## 三、预期输出

1. `outputs/analysis_video_<名>.json`（视频级聚合结果，`schema = beautyproof/video-analysis@1`）
   - `verdict.risk_level`：聚合风险（`high_risk / suspicious / credible / inconclusive`）
   - `verdict.flagged_frames` / `high_risk_frames`：**标出哪些帧触发了判定**
   - `frames[]`：逐帧判定（frame_id / timestamp / risk_level / reasons）
   - `risk_breakdown`：各档帧数统计
2. `reports/report_video_<名>.md`：与 `report_generator` 风格一致的视频级中文报告（含逐帧明细表）。
3. `outputs/video_frames/<名>/frame_*.jpg`：抽出来的帧，供人工抽查。
4. `outputs/<tool>_frame_*.json`：每帧各自的逐工具证据（沿用统一证据格式）。

**聚合规则（可审）**：
- 任一帧 `high_risk` → 视频 `high_risk`；
- 否则取所有帧里风险最高的那一档（`suspicious > credible > inconclusive`）；
- 并明确列出触发判定的帧号与时间点，便于人工定位。

## 五、诚实局限（必须在答辩/文档里讲清楚）

1. **抽帧覆盖率**：只分析采样帧，快速闪过（短于采样间隔）的编辑可能漏检。对剪辑密集的视频应提高 `--fps-sample` 或 `--max-frames`，但仍非逐帧全检。
2. **CPU 速度**：`full` 模式每帧都要加载 AIGC / TruFor 模型，单个视频可能需数分钟；11 个视频全跑 full 成本较高。建议先用 `--fast` 批量预览，仅对 flagged 视频跑 full。
3. **不替代图片结论**：视频级结论来自「采样帧的聚合」，本质是「至少这些帧有问题 / 采样帧没发现问题」，**不能当作「整段视频干净」的保证**。
4. **模型口径**：视频帧判定沿用图片流水线的全部阈值与开关（AIGC / TruFor / 跨模态等），与图片结论口径完全一致，可审计。
