## 5. 【推测】未证实的判断（不要当事实用）

1. **推测（置信中）**：`uniqId` 就是 OSS 对象键。依据是它无业务含义、100 位大小写字母数字串，与天池把竞赛文件放 `tianchi-competition` 桶的做法吻合；且用 uniqId 作 key 直读 OSS 得到 403（403 同时可能是"对象存在但无 public-read"或"对象不存在"两种解释，**无法区分**）。
2. **推测（置信低）**：登录后 `queryInformation` 可能返回**未打码**的真实文件名。依据仅是页面表头文案「数据文件名(注册之后可以下载)」。也可能登录前后都打码。**未证实。**
3. **推测（置信低）**：存在一个 `tianchi-competition` 之外的私有桶存放本次文件。我没有枚举到任何线索。
4. **并非推测**：仓库里 `docs/官方要求对照与冲一档路线_2026-10-02.md` 说「ossutil 可下」——**这个前提本次未得到验证**。实测 ossutil 命令接口同样返回 `用户未登陆.`，登录/报名之前 ossutil 也用不了（ossutil 命令里的 `-i/-k/--sts-token` 由服务端下发，不下发就无从构造）。

## 6. 结论：拿不到根因

1. 下载区文件名**在服务端就被打码**成 `【**********************.pptx`，匿名请求拿不到真名；
2. 唯一的两个取真实文件/真实命令入口（`/v3/proxy/competition/api/race/dataset/download`、`getOssutilDownloadTips`）**都校验登录态**，未登录返回 `用户未登陆.`；
3. OSS 对象**非匿名可读**（403），桶也**禁止匿名列举**（bucket policy）；
4. 本机没有阿里云/淘宝账号 cookie，所以**不是工具问题，是权限问题**。

### 要拿到文件的唯一路径（约 3 分钟，由人做）

1. 浏览器登录天池（淘宝/阿里云账号），进入 `https://tianchi.aliyun.com/competition/entrance/532496/information`；
2. 点「下载」→ 存到 `loreal-hackathon-beautyproof/data/official/`；
   或点「复制命令」→ 装 ossutil（`cn-shanghai`）后 `ossutil cp` 到本地；
3. 期望文件名形如 `【*.pptx】（若登录后端仍打码，就用 uniqId 当文件名，内容不受影响）`；
4. 存好后把文件放 `data/official/` 并把 sha256 发我，我继续读内容。

> 顺带：报名本身是「注册之后可以下载」的前置（前端对 `getOssutilDownloadTips` 还额外校验了 `o.signed`，即是否已报名）。
> 所以报名 → 登录后即可下，是两道门槛，不是一道。
