### 仓库内"存在但未进入生产判定"的模型（透明披露，防审核意外）

- `clip-vit-large-patch14`：跨模态实验残留，未进入生产链路。

### 合规红线自查（训练数据）

- ✅ **100% 团队自产**：上述全部图像由团队生成、采集或人工制作，无任何第三方数据集。
- ❌ **明确拒绝**以下数据源（见 `tools/train_aigen_v4.py` 头部"明确不做的"）：
  - **GenImage**（CC BY-NC-SA 非商用，与本赛事 20 万奖金商业场景冲突）；
  - **COCO**（与人脸隐私 + 美妆域无关）；
  - **任何品牌官方图 / 电商图 / 网络爬取图**（避免版权与品牌风险）；
  - **ImageNet 训练集**（仅作骨干初始化候选，实际未加载，见第四节）。
- ✅ **防数据泄漏**：`data/ai_cross` 验证份整体留作 held-out，绝不进训练；训练/验证按固定 `VAL_RATIO` 划分。

## 三、与队友"无跨队共享代码"自查说明

- **核心创新均为团队独立完成**，未在队伍之间或与外部赛队交换/复制代码：
  1. 统一八工具证据格式 `{tool, source_asset_id, observed, cannot_prove, evidence[]}`（工程抽象，全仓库共用）；
  2. 规则引擎 `rule_engine` 四档判定（`high_risk`/`suspicious`/`credible`/`inconclusive`）；
  3. 本域微调 AIGC 分类器 `beautyproof_aigen_v1→v5`（v4 为生产版）；
  4. 跨生成器验证方案（`data/ai_cross/` + 干净 held-out 划分法）；
  5. 流水线编排与可解释 Agent（`pipeline.py` + `planner.py` 波次调度与 R1–R5 跳过规则）；
  6. 图文交叉验证、文案体检、哈希指纹、C2PA 凭证解析、可解释报告、`validator` 护栏、多 Agent 圆桌、Web 取证台、离线自包含 demo。
- **第三方组件**：均通过公开仓库/包管理器按各自许可证获取（TruFor 官方仓库、PyPI/PaddleOCR、timm、HuggingFace 等），未从任何赛队取得私有代码。
- **可复现性**：仓库内 `requirements.txt` 锁定实测版本；`tools/setup_trufor.py` 可从官方源重建 TruFor 运行环境；自训模型可由 `tools/train_aigen_v4.py` 在 `data/` 自产数据上复训（见第四节命令）。
- **原创性佐证**：每个工具脚本头部均以注释标注"来源：原创"或"第三方调用 + 原创解析"（如 `aigc_tool.py`、`trufor_tool.py`、`ocr_tool.py`、`c2pa_tool.py`、`pipeline.py`、`report_generator.py`），与 `docs/SOURCES.md` 的原创清单一致。
