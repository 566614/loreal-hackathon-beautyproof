# BeautyProof 审核 Harness 与策略回放

首轮原型展示两条闭环。在线按证据缺口请求一次功效补证，离线用审核员标注比较固定的 v0、v1 取证顺序。两条路径调用同一个 `review_harness.decide`。取证动作、规则判断和引用可回查。

## 现场准备

企业入口使用团队授权的宣传材料和原始功效试验。预先确认产品、具体版本、市场、指标、数值和条件能逐字定位，记录试验来源、报告版本和页码。当前品牌资料目录中的 30 条品牌记录只提供宣传口径参照。真实主案例需要团队补齐授权功效试验。

以下示例中的产品与报告均为合成测试材料，仅用于离线流程复演。

1. 启动现有本地服务，进入企业审核入口，关闭 DeepSeek 辅助。
2. 发送 `核验宣传文案：【青蓝精华】2025版14天水分提升20%。`，在补充审核材料中填写市场 `中国`。
3. 打开报告的「检查记录」，确认下一步为「补充已核验功效试验」，下载决策轨迹。
4. 点击「添加已核验资料」，类型选「产品功效试验」。来源填 `合成流程测试报告`，产品填 `青蓝精华`，资料版本填 `测试报告1`，位置填 `第2页`，审核人填演示者代号，市场填 `中国`，产品版本填 `2025版`，摘录填写 `【青蓝精华】2025版14天水分提升20%。`。核对并勾选确认后保存。
5. 在检查记录中选择该条资料并点「补证后核验」。同一宣称从「证据不足」变为「有证据支持」，前后表和新增引用同时出现。整份报告的风险级别仍综合其他证据。
6. 用新一轮送审分别演示错版本资料、品牌宣称资料和冲突数值。错版本或类型不适用时仍显示证据不足，并转人工。条件一致且摘录数值为 40% 时显示冲突。

补证沿用上一回合的正文、产品、市场和图像观测，仅重新执行现有宣称及资料规则。图片工具和云模型在续审中没有调用。同一次送审最多成功补证一次，执行失败后允许重试。当前任务存于进程内存，过期或服务重启后需要重新送审。

## 记录一次取证顺序纠正

在「检查记录」展开「标注取证顺序并导出回放样本」。填写稳定的样本编号、来源组、分区、正确下一步和纠正理由，导出 JSON。同一宣传及其衍生图、同一功效试验使用相同来源组并放入同一分区。先在开发集上选择策略，再冻结留出样本和标签。留出结果用于采用判断。

导出观测只包含产品、版本、市场是否明确，宣称来源、量化与核验状态，OCR 状态、低置信项数量、冲突状态、是否已续审和证据编号。文件中不含宣传原句、图片、产品名称或试验摘录。样本编号、来源组和纠正理由请使用代号，避免写入敏感内容。导出的轨迹同时记录策略版本、动作、理由代码、执行状态与耗时。

## 复演离线策略循环

仓库提供 12 条合成决策样本，开发与留出各 6 条。v0 在图片文字待核对时先请求清晰原图。v1 在正文量化宣称已明确产品、具体版本及市场时，优先补功效试验。其余分支共用原规则。

从仓库根目录运行，仅需要 Python 标准库。

```powershell
python tools/replay_harness.py --output .local/harness/replay.json
```

合成样本的预期结果为开发集 v0 命中 5/6、v1 命中 6/6，留出集 v0 命中 4/6、v1 命中 6/6。该结果说明给定原型样本上的动作差异。真实改进效果需在团队授权、独立标注的样本上重测。

回放团队导出的样本时，每个分区至少 6 条，使用显式文件列表或合并为 JSON 数组。

PowerShell 中先把反馈文件展开成路径数组再传给 Python。

```powershell
$casePaths = @(Get-ChildItem -LiteralPath .local/harness/feedback -Filter '*.json' | ForEach-Object FullName)
python tools/replay_harness.py --cases $casePaths --output .local/harness/reviewed-replay.json
```

报告记录数据集 SHA-256、两分区逐案动作与命中数、改好和改坏的样本。候选策略由开发集选择，留出集至少改对一例且无新增错误动作时输出 `suggest_human_adoption`。否则输出 `keep_baseline` 并列出理由。候选没有获得采用建议时，现场展示导致拒绝的回归案例。回放只在允许的五个动作中选择，调用工具和模型的次数均为零，功效结论由在线规则负责。当前线上策略固定为 v0，采用建议供团队人工审查。

## 接口和验收

`POST /api/agent/turn` 增加 `evidence_followup=1`，与 `previous_job_id`、`role=reviewer` 和 `reference_ids` 一起提交。正文、产品及市场省略时沿用原送审值，提供不同值会拒绝。图片和选区应通过新一轮送审更新。补证仅接受后台已核验资料 ID。重复、并发、过期和跨角色请求返回明确错误，失败任务释放补证占用。

宣传报告的 `harness_trace` 包含 `schema`、`policy_version`、`observation`、`decision`、`state`、`followup_used`、`elapsed_ms`。`evidence_comparison` 包含每条宣称的原句、补证前后状态和新增引用，展示在本地工作台。导出回放时使用脱离原文的 observation。

验收运行相关 Agent、知识资料与回放测试，构建前端，再在浏览器分别复演补证支持、错版本、冲突和断网模式。线上展示真实资料补证，离线展示策略对照与采用门槛。提示词优化、跨会话恢复和模型权重微调作为后续路线，分别补充独立评测与训练记录后验收。
