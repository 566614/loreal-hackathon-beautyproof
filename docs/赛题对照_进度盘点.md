## 三、还差什么（按"会不会被评委扣分"排序）

### ✅ P0 · 文案侧 —— 已于 2026-09-23 补齐（8/8 评测通过）

赛题主题句写的是"识别**种草文章、评论区**与 AI 生成素材中被篡改、拼接或伪造的**文案与图片**"。
原来只能回答"这张图是不是假的"，答不了文案侧的问题，标签 #多模态 只兑现了一半。

**已补齐两个工具**（`tools/text_tool.py` + `tools/crossmodal_tool.py`）：

- **文案体检**：查违禁宣称，每条给法律出处（《广告法》第 9/17 条、《化妆品监督管理条例》第 43 条）。
  ⚠️ 刻意**不做**"AI 写作检测"——没有能证明该特征在本域有区分度的数据，就只统计、只提示、不给分数。
- **图文交叉验证**（杀手锏）：文案说"原相机实拍"、图却被判整图 AI 生成 → 硬矛盾。
  这依赖图像侧已能判真假，是只有图文双侧都做才拿得到的证据，通用检测器做不到。

**评测 8/8**（`data/text_cases.json` → `results/text_eval.json`），含 4 条**防误报**样本。
其中踩到的坑值得记：文案写"**非**实物拍摄"本是诚实说明，朴素词表匹配会把"实物拍摄"抠出来反报硬矛盾 —— 已加否定词识别。

最小可行补法（不重训大模型）：加一个文本工具，走统一证据格式，产出三类信号：
- 文案 AI 生成痕迹（困惑度 / 重复度 / 句式特征等统计信号）
- 文案与图上 OCR 文字的**跨模态一致性**（种草文说"亲测 7 天"，图上却写着别的）
- 评论区的刷量/模板化特征

第三条正好能接上我们的强项：**当"文案可疑 + 图片 AI 生成"同时成立时，结论才升级** —— 这是真正的多模态交叉验证，也是别的队不容易做的地方。

### ✅ P0 · 视频模态 —— 已于 2026-09-27 补齐（#多模态 第三条腿）

赛题标签 **#多模态**。原来只有「图」和「文」两条腿，而美妆种草的主流载体是短视频 ——
**只做图片等于漏掉最大的一块场景**，评委按「完成度·需求匹配」对照时这就是明摆着的缺口。

**接入方式（`tools/pipeline.py` 输入类型路由 + `tools/video_tool.py` + `tools/run_video.py`）**：

- **自动认输入类型**：`pipeline.main()` 里加了 `is_video_input()` / `expand_video_inputs()`，
  参数命中 `.mp4/.mov/.avi/.webm/.mkv`（或目录里含视频）就自动转调 `run_video`，
  **图片路径走原来的图像主路径，一条代码都没动**（红线：`analyze()` 未改）。
- **命令与图片侧完全一致**（评委不用记第二个命令）：
  ```bash
  python tools/pipeline.py demo/BeautyProof_演示视频.mp4 --max-frames 6 --fps-sample 0.5
  python tools/pipeline.py <含视频的目录> --fast
  # --fast / --json-only / --llm / --roundtable 全部透传（run_video → video_tool → 逐帧 analyze）
  ```
- **检测逻辑零重写**：抽帧 → 每帧复用 `pipeline.analyze()` 全套工具 → 聚合视频级结论。
- **聚合规则可审**：任一帧 `high_risk` → 视频 `high_risk`；否则取采样帧最高档；
  并标出触发帧的**帧号 + 时间点**。

**证据沿用统一格式**（`outputs/analysis_video_<名>.json`，不另起一套）：

| 字段 | 说明 |
|---|---|
| `source_asset_id` | 视频文件名；逐帧是该帧文件名 `frame_XXXX.jpg` |
| `frames[]` | 逐帧证据：帧号 / 时间点 / 风险等级 / 理由 / 该帧结果 JSON 路径 |
| `risk_level` + `reasons` | 视频级结论与依据（理由带 `[帧号 @ 秒数]` 出处） |
| `cannot_prove` | **本次证明不了什么** —— 抽帧覆盖率与未抽到的帧 |

每帧的逐工具证据落在 `outputs/<tool>_frame_XXXX.json`，与图片侧同一个
`{tool, source_asset_id, observed, cannot_prove, evidence[]}` 格式；
报告 `reports/report_video_<名>.md` 里每一句话都能追溯到这些文件。

**局限（必须在答辩里主动讲，不能等评委问）**：

1. **抽帧覆盖率**：实跑样例 6/4958 帧 = **0.12%**。只分析采样帧，短于采样间隔、
   快速闪过的编辑会漏检；提高 `--fps-sample` / `--max-frames` 也仍非逐帧全检。
2. **不能证明未抽到的帧**：视频级"可信"**不等于**"整段视频干净"，
   只能说明"被采样到的这些帧没发现问题"。这句话已写进 JSON 的 `cannot_prove`
   和报告的「能力边界」一节。
3. **成本**：full 模式每帧都要跑 AIGC / TruFor（OCR 单帧约 55s），单视频数分钟；
   `--fast` 先批量预览，只对被标出的视频跑 full。
4. 帧判定沿用图片流水线全部阈值与开关，与图片结论口径一致，可审计。

### 🔴 P0 · "Agent" 味道不够

赛题标签 **#智能体**，明确写"构建 Agent"。我们现在是"六个工具按固定顺序跑完"。
评委大概率会问：**"你的 Agent 会自己决定下一步查什么吗？"**

不必推翻架构。最小补法是给流水线加一层**条件调度**：
- hash 命中已知原图 → 直接出结论，不用跑 TruFor（省时间，且显得"会判断"）
- AIGC 判为整图 AI 生成 → 跳过 TruFor 的"局部篡改"解读（避免口径打架）
- 图上无文字 → 跳过 OCR 比对
- 结论为高风险 → 自动进人工复核队列

这套"根据中间结果决定下一步"就是评委想看的 Agent 决策过程，而且能顺带把单次鉴定时间砍下来。
