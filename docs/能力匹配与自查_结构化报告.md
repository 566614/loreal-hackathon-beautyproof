## 一、模型能力 × 任务需求匹配度评估

### 1.1 八工具模型清单与角色

| 环节 | 模型/工具 | 承担的任务 | 实测关键指标（产物可查） | 匹配度 |
|---|---|---|---|---|
| 局部篡改 | **TruFor**（CVPR'23） | 拼接/复制移动定位+热力图 | copy_move 0.9946、splice 1.0、干净图 0.3503/0.4113 未误报（`dataset_eval.json`） | ★★★★★ 强项 |
| 整图 AI | **beautyproof_aigen_v3**（自训 MobileNetV3，17MB） | "整张就是 AI 画的" | 见 1.2 演进表 | ★★★★（受控）/ ★★★（真实） |
| 出处元数据 | **c2patool + TC260** | 内容凭证/AIGC 标识 | incoming 30/30 与人工标注一致（`incoming_judge.json`） | ★★★★（依赖图带凭证） |
| 压缩差异 | ELA | PS 痕迹辅助信号 | 固有局限：PNG 自动跳过（R1）、压缩噪声可致误报（real_01 案例） | ★★★ 仅辅助 |
| 图上文字 | PaddleOCR PP-OCRv6 | 抄字供跨模态比对 | 中文可用；**34.5s/张偏慢** | ★★★ |
| 文案体检 | text_tool（规则+法条） | 违禁宣称核查 | 评测 8/8（含 4 条防误报）；20 篇口红笔记 0 违禁命中（`text_eval.json`） | ★★★★（规则域内强） |
| 图文交叉 | crossmodal_tool | 文案↔图像硬矛盾 | "原相机实拍" vs 整图 AI → 硬矛盾，差异化证据 | ★★★★ |
| 人话解释 | Qwen3-VL-4B（Ollama，CPU） | 报告翻译官 | 端到端验证通过；validator 护栏限制其不下结论 | ★★★（定位正确） |
| 视频模态 | moviepy（已装**未接入**） | 短视频抽帧鉴定 | 无产物 | ❌ 未兑现 |

### 1.2 AIGC 检测模型演进（能力画像，不含训练图自评）

| 版本 | 受控集 | 真实世界误报 | 跨生成器召回 | 定性结论 |
|---|---|---|---|---|
| v1 | 35 张 100%（留出 7 张也 100%，`capability_check.json`） | **66.2%**（74 张真实美妆，`aigen_v2_eval.json`） | 25%（8 张零样本，`cross_gen_test.json`） | "题库背熟"的实验室满分，现实会翻车 |
| v2 | — | **5.6%**（未训练验证集 1/18）；AI 召回 100% | 25% | 误报修复，跨生成器仍瘸 |
| **v3（现行）** | val_acc **0.963**（TP9/FN0/FP1/TN17） | 真图直测 **0.0002~0.047**，零回弹 | **100%**（held-out 5/5，`aigen_finetune_v3.json`） | 跨生成器修复；held-out 为 ImageGen 风格 |

### 1.3 匹配度结论（对照赛题四条任务）

| 赛题要求 | 能力匹配 | 结论 |
|---|---|---|
| ① 多模态（图+文） | 图侧 6 工具扎实；文侧规则级可用；**视频模态未接**（moviepy 已装未接线） | ✅ 达标，缺视频加分项 |
| ② 可解释判定 | 四段人话报告 + 统一证据链 + 热力图 + 方位 + Agent 人话理由 + LLM 翻译 + validator 六道关 | ✅ 强，是全项目最厚的一块 |
| ③ Agent | planner 波次调度（R1–R5/A1–A3）+ roundtable 四角色复核 | ✅ 达标；是"可解释调度 Agent"，不是自主探索型 Agent——答辩需主动这样定位，别被问穿 |
| ④ 数据集闭环 | batch_run + 多版本评测留痕 + 真实素材（AI 46 张/真实 89 张） | ✅ 达标但**规模偏薄**，答辩最易被追问 |

**总体判断：模型能力与任务需求总体匹配，无硬缺口；三处软肋 = 数据规模、跨生成器内核未验证（目前只验证到 ImageGen 风格）、视频模态未接。**

## 四、"泛B+C"逐项核查

> 口径：泛B+C = 方案 C 的取证流水线骨架 + 方案 B 的 Agent 协作（可解释调度 + 多角色圆桌）+ 方案 C 的 LLM 解释与护栏，并延伸方案 A 的多形态交付。

| 项 | 来源 | 证据 | 判定 |
|---|---|---|---|
| 八工具证据链 → 规则引擎四档 → 报告 | C | `pipeline.py` | ✅ |
| 可解释调度 Agent（波次 + R1–R5 + A1–A3，人话理由） | B | `planner.py` | ✅ |
| 多 Agent 圆桌（Image/Text/Source + Judge 共识） | B | `roundtable.py`（`--roundtable`） | ✅ |
| LLM 人话解释层（只翻译不下结论） | C | `llm_explainer.py`（`--llm`，Qwen3-VL-4B 已端到端验证） | ✅ |
| 护栏（六道关，越界措辞拦截） | C | `validator.py`（单测覆盖） | ✅ |
| 多形态交付（CLI/Web/离线/线上） | A | `web/app.py`、`demo/index.html`、线上站 | ✅ |
| 本域微调 AIGC（v1→v3，含跨生成器 held-out 方法论） | 泛B+C 之外的自研增强 | `train_aigen*.py` + results | ✅ |
| TC260 元数据判定 | 增强 | c2patool + `incoming_judge.json` 30/30 | ✅ |
| 视频模态 | — | moviepy 已装未接 | ❌ 未达标 |
| 真实评论区数据 | — | 无对口数据（需重抓） | ❌ 未达标 |
| MJ/SD/Flux 跨生成器内核验证 | — | 仅验证到 ImageGen 风格 | 🟡 部分 |

**结论：泛B+C 的代码与架构层 100% 满足；材料层缺 mp4 成片；数据层缺 MJ/SD/Flux 图与美妆评论区两项外部素材。**

## 五、评审视角预估：若现在直接参赛

### 5.1 两个打分框架

**框架一（天池技术验收，合格线判断）**：赛题四条硬要求全部命中且有产物 → 技术上稳过合格线，不存在"跑题"风险。

| 维度 | 自评 | 依据 |
|---|---|---|

| SUSTAINABLE | 5/5 | 全开源、可复现、数据集闭环可持续 |

### 5.2 预估结果

- **总分预估：39–44 / 50**（约 78–88 分位）
- **决赛入围概率：60–70%**；**获奖（前三）概率：25–35%**
- 天池赛道语境下（多支队伍、技术验收为门槛）：属**"稳定进决赛的强竞争者，但非无冕之王"**——能不能拿奖取决于答辩当天把团队 25 分讲出多少。

### 5.3 评分依据（评委视角的加减分）

加分项：① 真能跑的闭环 + 线上 Demo（多数队伍停留在 PPT）；② "翻车→修复"三段实证（66.2%→1.4%→跨生成器 100%），可信度远高于只报好数字的队；③ 可解释 Agent 有决策日志、每条理由可审计，正中赛题"可解释"题眼；④ 合规干净（LICENSE/NOTICE/public/数据红线），不踩资格线。

扣分/风险项：① 算法原创性一般（MobileNetV3 微调 + 开源工具编排，评委若追问"方法贡献"会吃亏）；② 数据规模小（AI 46/真实 89），统计说服力有限；③ 跨生成器 100% 是 ImageGen 风格口径，被问到 MJ/SD 时只能答"校准中"；④ 团队叙事（EMPATHY/AMBITION）未定稿未演练，25 分里可能丢 4–5 分；⑤ 演示视频无成片。
