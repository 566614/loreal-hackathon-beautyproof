## 二、逐项升级（含理由与影响）

### 1. `tools/threshold_sweep.py` — 修 NameError 崩溃
- **改动**：在既有 `try/except` 块内补 `BASELINE_SUSP`，用 `THRESHOLDS.get("aigc_suspicious", BASELINE_HIGH)`。
- **理由**：查 `rule_engine.py:40,65` 确认规则引擎语义是「AIGC 分数 ∈ [0.9, 0.99) → suspicious（灰带）」，
  即**灰带入口就是 `aigc_high_risk` 本身，并不存在独立的 `aigc_suspicious` 键**。用 `.get` 兼容将来新增该键，**不臆造当前不存在的阈值**。
- **影响**：脚本从「一跑就崩」变为可用。实测 `build_sweep()` 返回 101 个扫描点。仅影响该分析脚本，不在任何提交路径上。

### 2. `ai_label_tool.py` / `ocr_tool.py` / `make_defense_pptx.py` — `zip(..., strict=True)`
- **改动**：三处 `zip()` 补 `strict=True`。
- **理由**：这是**本次最重要的改动**。PaddleOCR 三个数组本应等长；一旦某版本/某图返回不等长，
  `zip` 会**静默截断到最短** → OCR 行被悄悄丢掉 → `ai_label` 读不到图上「AI生成」标识 → **漏检 → 判错**。
  这与本项目「证据链可信、每条工具必须写明不能证明什么」的立身之本直接冲突：**丢证据必须响亮报错，不能静默**。
- **影响**：正常路径行为完全不变（三者长度恒等）；异常情况下由「静默漏检」变为「抛错暴露」。

### 3. 8 处硬编码绝对路径 → 三级解析（环境变量 > PATH > 本机兜底）
| 文件 | 原来 | 现在 |
|---|---|---|
| `tools/batch_run.py:31` | 写死 venv python | `os.environ.get("BEAUTYPROOF_PYTHON") or sys.executable` |
| `tools/trufor_tool.py:38` | 写死 venv python | 同上 |
| `tools/push_via_api.py:26-27` | 写死 `gh.exe` / `git.exe` | `_find_exe()`：环境变量 → `shutil.which` → 兜底 → 清晰报错 |
| `tools/make_template.py:7` | 写死仓库绝对路径 | 由 `__file__` 推导 `data/` |
| `tools/video_tool.py:95` | 报错信息写死 pip 路径 | 动态用 `sys.executable` 生成 |
| `tools/_push_gitdata_api.py:14` | 写死 `gh.exe` | 环境变量 → `shutil.which` → 兜底 |
| `tools/_validate_crossgen.py:30`、`tools/download_vlm.py:13` | 文档字符串写死本机路径 | 改为 `./run.sh` 通用写法 / 泛化为 `<你的用户名>` |

- **理由**：官方评分明确包含「方案可复现」。评委换机/换 clone 路径复现时，写死路径会直接报错，是自伤。
- **影响**：**本机运行结果完全不变**（兜底路径仍在原处，且经 `run.sh` 启动时 `sys.executable` 正是当前 venv）——纯可移植性改进，零行为变更。

### 4. `web/app.py` — Web 服务加固
| 改动 | 位置 | 理由 |
|---|---|---|
| `job()` 查不到返回 **404 + `status:"not_found"`** | `web/app.py` `job()` | 原实现 `JOBS[job_id]` 抛 KeyError → 500。页面轮询过期 id 时只能显示"失败"，分不清是任务失败还是 id 无效 |
| `MAX_JOBS=64` + `_prune_jobs()` | `web/app.py` 模块级 | 每个 job 存完整 analysis（含原图 data URI 可达数 MB），长时间演示或被反复刷接口会无限吃内存。淘汰顺序：先删已完结的，仍超限再按插入顺序删最旧，**绝不删正在跑的** |
| `_safe_stem()` 白名单 | `web/app.py` | 把 stem 拼进文件路径前的纵深防御。Werkzeug 默认 string 转换器已挡掉常规 `../`，但线上 demo 公开可访问、且 `%2F` 在不同反代下解码行为不一致 |
| 损坏 JSON 返回明确 500 而非抛栈 | `web/app.py` `sample()` | 可诊断性 |

### 5. `web/review_app.py` — 同上 + 修脆弱写法
- **`load_analysis()` 内加白名单** → 一次覆盖本文件所有读结果端点（`/api/review/<stem>`、`/api/review` POST、队列接口），改动面最小。
- **`report()` 里 `err if 'err' in dir() else ""` → 显式 `err = None`**：原写法靠运行时 `dir()` 自省探测局部变量是否存在，语义脆弱。

### 6. 4 处异常链（B904）
`tools/export_pdf.py:414,450`、`tools/pipeline.py:312`、`tools/video_tool.py:93` 补 `from exc` / `from e`。
- **理由**：不补 `from` 时 Python 打印两段堆叠，根因被埋在中间。对本项目尤其不该——**报错可追溯性就是可信度**。
- **影响**：纯附加 `__cause__`，**零行为变化**。实测 `ExportError.__cause__ == FileNotFoundError`。

### 7. 代码卫生 41 项（ruff `--fix`）
F401 未用 import 17 → 0；F541 无占位 f-string 24 → 0。
> ⚠️ 其中 `ablation_eval.py` / `cascade_eval.py` / `spectral_calib.py` 的未用导入曾疑似「副作用导入」
> （项目有过「v4 当年缺 config 静默回退旧模型还报通过」的前车之鉴）。**动手前先确认 `cascade_eval.pin_model()` 是函数而非模块级副作用**，
> 确认后才动手，改完 17 个核心模块导入 + 151 项测试双验证。

### 8. 新增 `tests/test_web_smoke.py`（12 项）— 本轮性价比最高的补充
- **理由**：三个 Flask 服务是**评审实际打开的演示入口**，但此前自动化覆盖率为 **0**；且本轮新增的 stem 白名单、job 404、JOBS 上限三处行为**没有测试就会被下次改动悄悄改回去**。
- **覆盖**：样本列表 / 合法标识取结果 / 空上传 400 / 复核队列可读 / 内容核验首页可渲染 / 4 组恶意 stem 一律 404 / 不存在的 job 返回 404（**该 bug 的回归测试**）/ MAX_JOBS 上限存在。
- **纪律**：只测 HTTP 契约（状态码 + 关键字段）不碰内部实现，避免测试变脆；依赖外部产物的用 `pytest.skip` 并说明原因，**不让「没跑」伪装成「通过」**。
- **影响**：**纯加文件，未修改任何生产代码**。测试数 139 → 151，Web 层覆盖率 0% → 55%/66%/57%。
